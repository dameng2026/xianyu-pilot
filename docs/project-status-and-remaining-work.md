# 闲鱼自动发货与 Windows 便携版：当前进度及未完成清单

更新日期：2026-10-29（北京时间）

核对代码基线：`21d8749`，分支 `codex/windows-portable-host`。

范围：闲鱼自动发货核心链路、资产安全、Windows 绿色便携交付。不增加外部聊天机器人。

## 1. 目前能不能直接作为成品使用

**还不能作为已经验收通过的真实自动发货成品交付。**

目前已经完成底层安全逻辑、离线测试、安全工作台，以及 Windows 宿主和 GitHub 打包流程的代码。还缺真实账号接入、官方接口联调、完整配置界面、实际 EXE 构建结果和实机验收。

普通启动仍未装配真实平台运行时，因此不会自动登录闲鱼、接收真实订单或向买家发送卡密。这是当前明确的安全边界，不是打开某个开关就已经完成真实联调。

状态口径：

- **已实现并测试**：对应代码已有本地测试证据。
- **已写代码，待验证**：代码存在，但缺少对应运行环境或端到端验证。
- **未接通/待开发**：仍需补实现、界面或生产入口。
- **待实机验收**：不能用 Mock、代码检查或 GitHub runner 替代的验证。

## 3. 已经有证据的部分，不必推倒重写

1. **库存防重与未知锁定**：`BEGIN IMMEDIATE`、条件更新及唯一占用关系；未知结果不回库，不重新分配。
2. **A/B 两阶段**：A 为内容触达，B 为平台履约。B 补偿使用独立操作，不重新发卡。
3. **逐段交付**：已确认段跳过；明确未发送且允许重试的失败段才可重试。普通超时仍是未知。
4. **只读快照**：模板、说明、操作标识和身份冻结；新任务图片复制到 `data/assets/.snapshots/`。
5. **组合与数量**：购 N 件分配 N 条不同卡密；说明、图片和链接默认每单一份；库存不足整单暂停。
6. **本地工作台**：可看订单分段状态、待人工核对高亮、冻结素材与审计；已提供官方查询和 B 单独补偿接口，但普通离线启动不具备真实调用条件。
7. **便携路径基线**：数据锚定程序旁 `data/`；禁止路径穿越及目录联接，权限不足阻断；Python 临时文件重定向。
8. **生命周期逻辑**：暂停原因互不覆盖；旧恢复请求不能覆盖新暂停；退出等待在途提交。

## 4. P0：真实自动发货前必须补齐

### P0-1 正式账号与扫码登录链路

**现状**：Windows 宿主目前只打开本地安全控制台。正式扫码登录、账号绑定和登录资料尚未接通。控制台浏览器主动禁止外部页面和文件选择，不能直接拿它充当闲鱼登录窗口。

待完成：

- [ ] 独立、受控的闲鱼登录入口和账号管理界面。
- [ ] 登录成功后核验卖家身份，把账号与本地订单、商品绑定。
- [ ] 将账号资料放到 `data/profiles/` 的独立目录，与本地控制台资料分开。
- [ ] 本机凭据的加密保存、刷新、失效处理和重新授权流程。
- [ ] 明确同电脑移动和跨电脑迁移时，哪些资料可保留、哪些场景必须重新登录。

完成标准：可从桌面登录授权账号，退出重启后按设计恢复；失效时暂停并提示；不依赖旧 MySQL 凭据路径，不把业务资料写到系统用户目录。

### P0-2 核实真实闲鱼接口契约

**现状**：签名请求和严格解析框架已写，`contract_verified` 默认关闭。尚未取得真实账号返回样例验证目标接口，不能断言当前接口参数和字段已可用。

待完成：

- [ ] 核实卖家订单列表/详情接口、分页、订单号、状态、SKU、数量、金额与退款字段。
- [ ] 核实 IM 官方付款卡片的真实结构和相关身份字段。
- [ ] 核实文本、图片发送的正面回执及超时语义。
- [ ] 核实平台“无需物流确认发货”请求及返回结果。
- [ ] 将授权取得的脱敏样例纳入契约回归，拒绝缺字段和未知状态。

完成标准：真实返回可被显式适配器正确解析；失败不隐式切接口，也不把未知状态当付款成功。

### P0-3 把生产运行时真正装配到桌面入口

**现状**：`compose_official_runtime(...)` 和依赖注入入口存在，但 `run_portable.py` 创建 `DesktopBackend` 时没有提供 `platform_runtime`。普通 EXE 入口因此仍是离线模式。

待完成：

- [ ] 提供已验证的 `SellerSession` 来源与凭据更新回调。
- [ ] 实现可信的买家/商品会话解析，不能猜聊天 CID。
- [ ] 将已登录账号、IM、订单探针、图片上传和履约网关装配进同一个桌面生命周期。
- [ ] 验证首次启动、重启、账号失效、重连、暂停与退出之间的行为。
- [ ] 确保未登录或核验失败时保持离线/暂停，不显示绿色运行状态。

完成标准：同一桌面程序能够安全启动真实双监听，真实官方订单进入既有 SQLite 状态机；重复事件不产生第二次卡密分配。

### P0-4 跑通真实订单与异常场景

- [ ] 授权小号完成一笔 0.01 元订单：付款 → 卡密触达 → 平台确认 → 本地完成。
- [ ] 验证真实多件订单和不同 SKU，数量、卡密分组及说明一致。
- [ ] 验证未付款、关闭、退款中、身份不一致和库存不足均不出库。
- [ ] 验证真实消息超时、图片超时、B 超时、断网及重启不二次发卡。
- [ ] 验证 WS 漏通知时由轮询补获，重复推送与轮询重叠不重复发货。
- [ ] 记录真实时延；“3 秒”仅作为正常 WS 路径的验收目标，15–30 秒轮询兜底不能承诺同样时延。

完成标准：有脱敏的订单、操作、回执和状态转换证据。Mock 全通过不能替代这一项。

## 5. P1：首版可用性和人工处理仍需开发

### P1-1 完整桌面业务界面

目前可用的是安全工作台，不能认为原 Vue 的所有页面都已完成 SQLite 适配。

- [ ] 接通首版必需的账号、商品、卡密仓库及订单操作页面。
- [ ] 实现组合内容编辑与排序、卡密模板、SKU 映射、按单/按件配置和预览。
- [ ] 在界面处理配置版本冲突、缺货、停用、日额度等结果。
- [ ] 适配本地会话和接口，隐藏未迁移功能，避免继续依赖服务器登录/MySQL/Redis。

完成标准：用户可以从登录、选商品、导卡、配规则到看订单完整操作，无需手工发 JSON 或改数据库。

### P1-2 素材导入与管理

后端能引用和冻结已存在的相对路径，但还没有完整素材导入 UI。当前内嵌控制台的文件选择和下载是禁止的。

- [ ] 提供受控的原生文件选择/素材导入入口，将图片复制到 `data/assets/`。
- [ ] 校验类型、大小、相对路径和目录边界，提供预览与规则引用。
- [ ] 处理改名、删除、损坏和历史快照引用；不能删除仍被在途/未知订单依赖的素材。
- [ ] 如首版开放导出，提供固定写入 `data/` 的导出路径，不直接放开浏览器任意下载。

### P1-3 未知消息段的人工核对闭环

目前工作台可以查官方状态、补偿 B；底层存在带操作人和证据的内容核对服务，但未开放完整的 A 段人工核对界面/接口。

- [ ] 展示待核对段、操作编号、尝试与回执线索。
- [ ] 提交并校验操作人和正面送达证据，保留不可混淆的审计。
- [ ] 在证实已送达后，只继续其余安全步骤。
- [ ] 没有证据时继续锁定，不提供“未知直接回库”“未知改待发送”或“整单重发”捷径。

完成标准：卖家能通过界面处理异常，又不会绕过永久绑定和防重复发卡约束。官方已发货只能证明 B，不能替代 A 的送达证据。

### P1-4 备份、恢复和升级

`data/backups/` 已创建，但完整的备份/恢复产品流程和升级验收尚未完成。

- [ ] 使用 SQLite 备份接口或完全停机备份，不能在线只复制主数据库而忽略 WAL。
- [ ] 确定素材、凭据和审计的备份范围、保护方式及保留规则。
- [ ] 提供恢复校验、失败提示和升级前备份说明。
- [ ] 在有历史订单、库存和未知任务的真实数据副本上验证升级，确认卡密不会重新入库。
- [ ] 写清楚更新 EXE/运行组件时如何保留完整 `data/`，以及迁移失败如何处理。

### P1-5 首版涉及的旧入口与代码质量收尾

- [ ] 逐项核对首版页面所需接口；当前未适配接口返回 503，不能只搬旧页面就宣布可用。
- [ ] 核查旧恢复器、旧存储入口和新运行时之间不会存在第二条实际发货路径。
- [ ] 处理前次检查发现的原有前端 lint 错误，再完成首版界面的构建和端到端回归。

非核心旧功能是否迁移需按首版范围决定，不要求为了发货首版把所有原服务端功能重做一遍。

## 7. P1：必须在真实 Windows 环境完成的验收

| 待验收项目 | 验收方法 | 通过标准 |
| --- | --- | --- |
| 干净系统免安装 | 在无 Python/Node/Git/额外浏览器运行时的干净 VM 解压双击 | 界面、数据库、内嵌渲染正常，无需补装环境 |
| 真实换盘符/U 盘 | 完全退出后移动整包，再启动 | 历史订单、库存、快照、素材完整；登录按已确定方案保留或明确要求重新授权 |
| 快捷方式/外部调用 | 从不同工作目录及桌面快捷方式启动 | 唯一数据根仍为当前 EXE 旁 `data/` |
| 系统盘业务写入隔离 | 跟踪主进程与 QtWebEngineProcess 全程文件 I/O | 无业务数据写入 C:/Users、AppData 或系统 Temp；不能只查看数据库路径 |
| 权限不足与目录联接 | 在不可写目录、外部联接目录等场景启动 | 明确报错阻断，不静默换存储位置 |
| 原生托盘 | 关闭窗口、双击、菜单操作、重复启动 | 关闭仅隐藏，单实例有效；状态和告警真实准确 |
| 隐藏后真实发货 | 连接真实账号，隐藏窗口，再完成测试订单 | 监听、状态核验和交付持续运行，仍无重复发卡 |
| 休眠/断网/失效 | 测试睡眠唤醒、网络恢复及账号失效 | 暂停并告警，先核验再恢复；手动暂停不被清除 |
| 退出与断电恢复 | 测试在途退出、强制结束及物理断电 | 未知保留绑定，已确认段不重发，不能出现一卡二卖 |

补充较长时间运行验证：关注 IM 重连、轮询负载、内存、日志增长及大量历史记录；测试报告应注明实际时长，不预先宣称通过。

## 8. 当前不支持、但不自动算作首版必做的内容

- 同一平台订单含多个商品明细的复杂交付。
- 购买 1 件却需要消耗多条卡密的套餐；目前是购 N 件分配 N 条，购 3 件已覆盖 3 张卡密。
- 旧货源库 `sourceId` 等未迁移来源，以及收货/评价时机的额外自动化。
- 无证据释放未知卡密、强行重发整单：这不是待补功能，而是继续禁止的行为。
- QQ 等外部聊天机器人：不在本项目当前目标内。

上述扩展应另行确认范围，不能为了覆盖旧系统所有功能拖延自动发货首版，也不能静默套用不兼容配置。

## 9. 建议后续执行顺序

1. **先获得 GitHub 便携预览包**：尽早暴露 Qt、资源和冻结运行时问题；这项可与真实接入并行推进。
2. **接通登录、凭据与接口契约**：准备授权测试账号和脱敏样例，继续保持生产发送默认关闭。
3. **装配真实运行时并完成小额试单**：验证真实 A/B、幂等和异常补偿。
4. **补齐规则、素材和异常处理界面**：让用户无需改数据库即可操作。
5. **完成备份升级与实机验收**：干净 VM、换盘符、I/O、托盘、休眠和断电逐项留证。
6. **再做首版交付**：发布有版本、校验和、使用说明及已知限制的便携包。

在 P0 项目完成、GitHub 实际构建通过和实机验收结束前，不把“本地测试通过”标为“真实闲鱼自动发货便携成品已完成”。
