# 闲鱼自动发货与 Windows 便携版设计

日期：2026-10-29。基线：`ac55305`。本项目继续增量改造原 Python API、Vue、订单、卡密及发货记录，不引入 QQ、外部聊天机器人或另一套演示业务库。

后续进展：官方状态核验、双监听和统一商品/SKU 配置适配见 [官方订单核验说明](official-order-delivery.md)；005 版本的永久卡密绑定、图片副本、只读快照和安全工作台见 [资产安全与恢复](delivery-safety-recovery.md)。下文阶段 1 的 Mock 限制描述其原始交付；普通启动仍离线，真实运行需经过契约验证后显式装配。

## 交付阶段与本次范围

1. **本次阶段 1**：真实 SQLite 事务下的本地订单、卡密原子占用、冻结内容、逐段操作回执、平台确认阶段、未知锁定、启动恢复、审计；执行仅允许测试注入的 Mock。开放只读订单/发货详情，不开放 HTTP 模拟付款或真实发送入口。
2. 阶段 2：将规范接到原商品配置页面，统一 `delivery_rule` / 商品 JSON 两条路径，完成 SKU 选择、素材管理与编排 UI。阶段 1 的服务层提供数量、SKU 和有序步骤契约供下一阶段使用。
3. 阶段 3：账号/订单同步、付款可信验证、消息长连接与真实网关。未经核验的手工数据与 Mock 结果不得成为真实发货资格。
4. 阶段 4：Windows 便携 EXE、私有运行环境与静态资源、托盘、休眠和断网处理、干净 Windows 验收。阶段 1 不宣称已经交付 EXE。

## 不变式

- 订单按 `(account_id, external_order_id)` 去重，内容身份（买家、商品、SKU、数量）改变须报冲突，不能建立第二次交付。
- 任务记录继续使用原 `delivery_record`。每个订单只产生一个首发任务；显式补发以后另设操作类型并记录原因，本阶段不提供隐式补发。
- 付款资格来自可信平台适配器；Mock 单独标识。HTTP 请求不能伪造平台核验，生产网关尚未装配。
- 一次事务先核验并占齐整单全部库存，才生成步骤。缺货保留订单和待补货记录，但不领取任何卡密、不发送问候语。
- 唯一占用关系约束一条卡密不能属于两个订单；同单重试使用原卡密、原内容和原操作编号。
- 写入使用 `BEGIN IMMEDIATE`、WAL、`synchronous=FULL`；提交后才允许外部操作。事务中不等待网络。
- 逐段先提交 `sending` 与稳定操作编号，再外呼，再记录回执。外呼抛错、超时或外呼后落库失败，均保留未知风险，禁止自动重发。
- 只有网关明确报告“未发送且可重试”才能重试失败段；未知状态即使已经很久也不能改成可重试。
- 消息交付与平台确认分开。平台确认失败或未知永远不回到消息发送，也不重新分配卡密。
- 已发送、未知或带历史占用的卡密不自动释放。首次实现不提供取消释放与未知转未发送入口；后续须基于正面证据、审计和显式操作实现。

## 数据结构

沿用 `xianyu_trade_order`、`xianyu_trade_order_item`、`delivery_record`、`card_item`。新增增量迁移，旧迁移保持校验和不变：

| 结构 | 内容与约束 |
| --- | --- |
| 原订单扩展 | 核验来源 `mock/platform`、支付核验记录；账号与平台订单唯一 |
| 原发货记录扩展 | 唯一订单引用、订单身份指纹、完整规则快照、内容快照、运行来源、任务状态、平台确认状态 |
| `delivery_card_reservation` | 关联原订单/发货记录/卡密，`card_id` 唯一；reserved/delivered/unknown |
| `delivery_segment` | 有序文本/卡密/图片/链接，冻结后的载荷、卡密引用、状态、稳定操作编号；任务内顺序唯一 |
| `delivery_step_attempt` | 每次外呼开始、结束、结果分类、回执，含平台确认；未知不自动再发 |
| `delivery_audit` | 状态转换、人工核验理由和关联编号；不记录卡密明文 |

卡密明文只存在业务数据库中的原库存及冻结内容内，不写控制台、异常消息或审计摘要。数据库本身是敏感数据；正式账号接入前需完成本机凭据保护与备份保护方案，不能把整个数据库视为无敏感信息的日志。

## 状态与恢复

任务：`stock_blocked → ready → delivering → confirmation_pending → completed`；段落失败为 `failed`，未确认结果为 `needs_review`。逐段状态：`pending/sending/confirmed/failed/unknown`。确认阶段独立记录这些状态，另有 `manual_pending` 表示等待卖家提供平台已发货证据；关闭自动平台确认不能把任务直接当作已完成。

原卡密仍使用 `0 可用 / 1 占用 / 2 已交付 / 3 无效 / 4 错误`，补充占用关系表达 unknown；已有库存管理接口不可解除任务占用。卡密段回执 confirmed 后标记已交付；后面的说明失败不使卡密回库。unknown 时保留原订单和领取令牌，并转人工核对。

恢复在持有数据目录单实例锁时执行。遗留 `sending` 段和确认步骤转 `unknown`、任务转 `needs_review`；不删除步骤、不清除卡密、不创建新编号。已确认段保持不变。运行中的其他执行器看到 `sending` 只返回正在执行，不能抢占。重复提交、并发执行和重启均不以时间窗口作为重复交付依据。

人工核对 confirmed 必须显式提交说明及证据引用，保留审计。确认某段已送达后，只允许继续剩余步骤；确认平台已发货后完成任务。不实现“未知直接重新发送”的捷径。

## 编排与数量契约

规则快照包含版本、SKU、按顺序排列的步骤；步骤类型 `text/card/image/link`，发送范围 `order/item`。可复用原文字、图片和链接网关，阶段 3 再适配真实调用。

- 卡密每件分配一条，共 N 条；同一规则暂只允许一个卡密步骤，避免一次购买重复消耗。多卡套餐后续显式扩展。
- 卡密字段分别提供 `{卡号}`、`{密码}`、`{卡密}`，不把密码当作完整卡密；单段模板有相应占位符校验。
- 文字/图片/链接默认整单一次，可设置每件一次。按配置的步骤顺序展开，每件步骤按件号排序。
- 图片只接受 `assets/...` 下相对引用，禁止绝对路径、`..`、盘符、符号链接或目录跳出。阶段 2 导入素材时复制并固定版本，阶段 3 上传平台时再生成平台 URL。
- 触发时完整复制规则与展开内容。已开始任务不受规则修改影响；相同订单重新触发返回原任务。
- SKU 匹配只接受完全匹配；缺少匹配配置阻断，不能静默套用其他 SKU。

## 唯一便携数据根

打包运行根由 `Path(sys.executable).resolve().parent` 决定；源码开发使用项目根。所有应用运行文件位于根目录 `data/`，固定创建 `assets/profiles/logs/tmp/backups`，未来缓存和导出也放在 `data/` 内。SQL 数据库和 WAL/SHM 位于 `data/`。

启动在导入业务和浏览器组件前检查目录及数据库路径，拒绝逃逸链接，实测创建文件并同步；失败在 Windows 弹窗并终止。运行时设置 `TEMP/TMP/TMPDIR` 和 Python tempfile 到 `data/tmp`，SQLite 临时存储使用内存，不回退用户目录。禁用运行时 pyc 写入。只在源码开发/构建时允许构建工具按工作区规则生成产物。

便携包采用目录式运行组件和前端资源，避免运行时自行解压到系统 Temp。后续浏览器 profile/cache/crash dump、WebView、日志组件、图片上传临时文件、爬虫截图都必须逐项重定向。系统自身维护的诊断记录不等于应用可控制的业务文件；阶段 4 需用文件访问跟踪验证应用及其子进程的写入路径，不能仅凭主数据库位置宣称全部闭环。

素材只存相对路径，换盘符无需改数据库。移动前完整退出；备份用 SQLite 备份接口或停机复制整个 data（不能在线只复制 app.sqlite3 忽略 WAL）。正式账号跨电脑迁移需重新授权的情况应明确提示。

## 桌面生命周期（阶段 4）

本轮已增加宿主、托盘、原生电源事件和 GitHub onedir 构建代码，当前实现及未完成验收以 [Windows 便携说明](windows-portable.md) 为准；下文为最终产品要求，不能据此认为已经实机验收。

关闭窗口默认进托盘并提示“自动发货仍在后台运行”；托盘提供状态、暂停、恢复、打开和彻底退出。暂停阻止新外呼，不能声称取消已经开始的外部操作。

休眠/断网/账号失效先暂停；恢复后核验账号、付款与订单、已有消息回执及平台发货状态，再恢复安全任务。遗留不确定步骤保留人工核对，不以“网络已恢复”触发重发。退出先停止领取新工作，等待或标记在途操作，持久化后关闭宿主。

## 验收矩阵

阶段 1 使用临时隔离数据库和禁止网络的测试；生产应用不内置可通过 HTTP 调用的 Mock 发货入口。

1. 同一订单重复入站与并发触发只建一个任务，只领取 N 条；不同订单无重叠。
2. 整单缺货时零占用、零外呼；补足后复用同一订单创建完整任务。
3. 卡密与完整说明、图片、链接按序；说明按单/按件展开数量正确。
4. 中途数据库异常全事务回滚；外呼不持数据库写锁。
5. 卡密成功、图片明确失败后仅重试图片，卡密和问候不重发。
6. 发送超时、崩溃或落库失败后转未知；重启和旧恢复函数不释放、不自动重发。
7. 平台确认失败后只调用平台确认；平台确认未知可对账/人工确认，不能重发内容。
8. 原规则修改、进程重启、换目录后任务快照与操作编号保持。
9. Mock 核验与回执明确标识，真实发送接口保持不可用。
10. EXE 根、cwd、环境变量、路径穿越、链接逃逸、不可写目录与 tempfile 位置验证；完整浏览器与托盘验收留至阶段 4。
