# 原系统自动发货增量改造

确认日期：2026-10-29。

## 实施范围

沿用原后台、原 API 和现有数据结构。自动发货从 `apps/web/src/pages/AutoDeliveryPage.vue` 进入，复用现有货源库、卡密仓库、订单及发货记录。不把独立桌面演示当作原系统改造的交付物。

原发货执行继续使用 `ws_delivery_handler.py`、`realtime_delivery.py` 及现有恢复机制；新增修改不得另外建立订单、卡密或发送状态系统。真实账号联调和真实订单发送不属于离线开发验证。

## 本轮修复：直接录入卡密与原仓库衔接

原自动发货页允许在配置时直接录入卡密，但 `POST /api/cards` 创建分组后未返回 ID。卡密仓库期望数字 ID，自动发货页则读取对象中的 ID，造成分组创建后无法继续导入。

修复后：

- 创建分组返回已提交的数字 ID；无法取得 ID 时回滚创建。
- 自动发货页用该 ID 向原卡密仓库导入，保留原来的卡号密码分隔格式。
- 已确认的分组编号保留在当前配置表单中。导入失败后，在同一表单重试复用原分组；重复卡密由原导入接口去重。
- 只有导入统计完整、没有失败条目时，才继续绑定发货规则；部分成功或回执不明时保留录入内容供核对。
- 导入成功后切换到已有分组。后续保存规则失败时，再次保存不重复建组或导入。
- 分组创建请求结果不明时，当前表单停止再次自动创建，提示先去卡密仓库核对。
- 保存期间禁止关闭弹窗、切换时机和修改输入，避免异步请求绑定到另一份配置。

这些保护没有增加数据库迁移，也不对历史库存做批量修改。表单中的重试上下文不跨浏览器刷新保存；遇到结果不明应先到卡密仓库核对，不应关闭后重新导入。
