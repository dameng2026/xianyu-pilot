# 本地工作流使用说明

产品方向已于 2026-10-29 确认为“自动发货优先、QQ 按需启用”。当前不推进真实 QQ 接入；页面调整目标及下一步验收标准见 [自动发货产品标准](auto-delivery-product-standard.md)。本文介绍现有版本的实际能力。

当前版本是可运行的 Windows 本机工作流：Python 服务、Vue 页面、SQLite 数据及本项目自行实现的 MCP 接口。无需 Docker、MySQL、Redis，也不安装、打包或调用 Tulpa；仅参考其受限工具、账号绑定、事件与回执分离的架构思路。

## 启动与停止

在仓库根目录双击 `start-desktop-demo.bat`，访问 `http://127.0.0.1:15179`。页面右上角“停止服务”会结束本实例并保留数据。再次双击脚本可以继续使用原数据。

此电脑已准备项目独立的 `.venv-ci` 和 Node.js 22.23.1 / npm 10.9.8。启动器核对锁定依赖，构建页面后运行本机服务，不修改全局 Python 或现有数据库。其他开发电脑需要 Python 3.11–3.13、同版本 Node/npm；首次缺依赖时会创建 `.venv-desktop` 并按哈希锁安装，首次安装需要网络。当前不是自带运行环境的安装包。

数据固定保存在程序根目录的 `data/demo/`，数据库为 `demo.sqlite3`。不再提供 `-DataDir` 参数或 `XYA_DESKTOP_DATA_DIR` 覆盖。旧预览目录中的数据不会自动导入；停止旧实例并备份后，可自行复制到 `data/demo/`。

```powershell
Set-Location D:\xianyu-pilot
.\start-desktop-demo.bat -NoBrowser
```

同一目录只能运行一个宿主。启动时先锁目录、预留端口，再执行带校验和的追加迁移；不会执行旧 MySQL 迁移或读取根目录 `.env`。旧版演示的三个历史记录仍在原表中，不伪装成新工作流订单。

## 四个页面

| 页面 | 当前功能 |
| --- | --- |
| QQ 账号管理 | 用户自行登记手动、模拟或 OneBot 兼容接入；验证归属、健康检查、解绑；下方管理本项目 MCP 连接 |
| QQ 服务管理 | 账号、固定好友目标、请求模板、必填字段、超时、重试上限、执行许可、结果提取与失败话术 |
| 商品处理配置 | 直接发货 / QQ 处理二选一；参数来源、确认策略、交付模板和发货时机 |
| 任务工作台 | 手动登记订单，保存规则快照、参数、步骤、操作编号、回执、日志与人工操作 |

## 先体验直接发货

1. 在商品处理配置新增一项教程商品，选择“直接自动发货”，交付通道保留“本地模拟”。无需添加任何 QQ 账号。
2. 执行策略保留“需卖家确认”；发货确认可选“交付成功后自动模拟确认”。
3. 创建一笔虚构订单，查看任务的规则快照并确认执行。
4. 检查“回发买家”完成后才执行“确认闲鱼发货”，两步均标注模拟回执。

若选择人工交付，页面只在你明确记录已回发买家后，允许记录已在闲鱼确认发货；这些是人工记录，不是平台回执。

## 再体验 QQ 处理

1. 添加“本地模拟”账号并检测连接。其在线状态明确标为模拟，不证明真实 QQ 归属。
2. 为这个账号创建服务，目标可填 `demo-bot`，请求模板保留 `{value}` 和 `{request_id}`。
3. 添加 QQ 商品并选择服务、参数来源、执行策略和交付模板 `{result}`。
4. 创建虚构订单，补充参数、确认执行、审核结果，再查看交付及发货步骤。
5. 测试分段、重复、错误发送者、超时与发送结果不明等场景。

未验证账号只允许手动处理：卖家在 QQ 自行提交、人工记录已提交、回填结果并审核。本应用不会因此将账号标为已验证。

## 快照、修改和异常

- 商品和服务修改只产生新版本，不改变已创建任务。快照保存商品、服务、账号 ID 与验证代次、固定目标及模板。
- 执行前可显式修改处理方式、服务与交付内容，保留原快照，并重新确认。不是偷偷采用最新商品规则。
- 已提交 QQ 后不允许更换账号或服务覆盖原请求。可终止后续交付、人工核对结果或准备关联新任务。
- 订单编号在工作区内唯一；重复登记返回原任务。QQ、买家交付和发货分别保存步骤与稳定操作编号。
- 确认未执行的失败步骤可由卖家显式重试，受服务重试上限约束。发送回执丢失、超时及崩溃恢复后的不明结果禁止自动重发。
- QQ 通道按账号与目标暂停；不会阻止独立的直接发货商品。解除暂停是明确人工操作，不会重发旧请求。
- 已交付步骤不重复执行。交付或发货阶段中断时，卖家可以核对实际平台后记录成功，不必重新查询 QQ。
- 异常通过工作台统计、高亮列表、失败原因和处理按钮提醒。安抚话术仅生成预览和复制，真实闲鱼发送尚未接入。

## 真实 QQ 接入边界

MCP 是本项目对客户端开放的业务工具协议，不等同于 QQ 登录或消息传输。当前没有实现 QQ 原生登录协议，也没有安装第三方 QQ 程序。

现提供一个可替换的 OneBot v11 HTTP 兼容适配器：核对 `get_login_info` 和好友目录，向快照内好友发送纯文本，接收带签名的事件。用户需要自行准备已有的 QQ 接入器；不限定为 Tulpa、SnowLuma 或任何供应商账号。

只有用户自行配置 API Token、事件签名密钥，且账号身份与事件心跳均核对通过后，才允许自动提交。回调地址为 `http://127.0.0.1:15179/api/qq/events/<账号ID>`。事件需采用数组消息段，首版仅接受好友私聊文本及引用；心跳超过 90 秒或缓存缺口会暂停自动处理。签名采用 OneBot 11 标准定义的 HMAC-SHA1，并使用恒定时间比较。

结果需要匹配固定账号、好友和本次请求编号或原消息引用。真实分段回复不会仅因短暂安静就自动完成：默认先保存片段，由卖家核对完整性；自动提取只适用于用户核实的完整回复正则。正则在独立进程中运行，超时转人工。

真实 QQ 网络接口仅用本机测试替身验证，尚未拿用户真实账号联调。真实闲鱼付款通知、聊天接入、发送买家消息和确认发货 API 均未接入，所以当前任务来源是卖家手动登记，自动交付是明确标注的模拟。

## 数据、安全与隔离

当前是一个 Windows 用户的本机工作区，不是已经上线的多租户 SaaS。数据和外键带工作区归属；调用方不能在请求体或 Header 中切换租户，也不能引用其他工作区的账号、服务、商品或任务。用户登录、SaaS 租户认证与远程供应商后台不在本批范围。

API Token 与事件密钥由当前 Windows 用户的 DPAPI 加密，列表不回传。解密失败不回退明文。MCP 令牌只保存摘要，按商品授权、限时、可撤销。任务正文、结果和商品模板当前仍以明文保存在本机 SQLite，尚未完成所有业务数据加密。

服务只监听 `127.0.0.1`，校验 Host、Origin、请求体大小。界面使用 HttpOnly 同站会话及 CSRF；MCP 单独验证 Bearer；QQ 回调单独验证签名、账号、时间和消息去重，不会放宽普通界面的校验。此界面会话是本机单用户方案，不抵御具有同一 Windows 用户权限的恶意程序，也不是未来桌面受信窗口 IPC 方案。

停止服务后备份整个数据目录，避免遗漏 SQLite WAL。默认列出最近 100 条任务，最多 500 条未结束任务；QQ 事件每账号最多保留 1,000 条，丢弃缺口会被检测。源码目录与业务数据应分别备份。

## 开发验证

```powershell
Set-Location D:\xianyu-pilot
$env:APP_ENV = 'test'
$env:PYTHONPATH = 'apps/api'
.\.venv-ci\Scripts\python.exe -m pytest apps/api/tests -q --basetemp=.tmp/workflow-tests
```

Windows DPAPI 测试需在正常 Windows 用户环境执行。Linux CI 只跳过 Windows 专属加密测试，其余使用明确注入的测试加密器，不作为运行时降级路径。

前端在 `apps/web` 执行 `npm.cmd run build:desktop`，产物为忽略的 `apps/desktop/web-dist`。启动脚本名沿用 `start-desktop-demo.bat`，便于从上一版继续使用。
