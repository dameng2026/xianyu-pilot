# 资产安全、分段恢复与桌面核对

本轮在原 SQLite 订单、卡密和发货记录上加强安全边界。真实发送依然需要受信宿主装配已验证的官方适配器；普通桌面启动只提供配置和本地查询，不会登录账号或向买家发送消息。

## 数据与不可逆约束

新增迁移 `005_delivery_safety.sql`，不改动已发布的 001–004 迁移。数据库使用 `BEGIN IMMEDIATE`、WAL、FULL 同步和外键；事务内提交出库意图后，才在事务外调用网络。

- 一笔订单只有一个桌面发货记录。一张卡只有一条永久占用关系。
- 原子认领同时写入 `status=1`、`claim_token`、`used_order_id`，并检查条件更新影响行数为 1；数量不足整单不认领。
- 卡密处于占用状态时计入锁定数量；收到卡密段明确正面回执后才计入已用数量。
- 数据库触发器禁止释放、删除、换卡、变更订单归属、改写卡密正文或清除认领标识；结果未知也不例外。确认送达的卡密保留永久归属。
- 发货记录的模板快照、身份指纹、平台商品 ID、操作 ID 和分段载荷只读。已确认段不能降级，未知段不能改回待发送。
- 审计、尝试记录和状态明细写入 `data/app.sqlite3`；只读工作台和审计响应不返回卡密正文。

这些约束用于阻断应用误操作，不能防止拥有数据库文件写权限的人删库或移除触发器。跨平台网络与本地数据库之间不存在原子提交，因此系统采取“结果未知即暂停”，不声称外部接口天然支持恰好一次。

## A/B 两阶段和断点补发

阶段 A 为按序发送问候、卡密、说明、图片、链接。每段有独立的稳定操作标识、尝试记录和回执。阶段 B 为平台履约，使用另一操作标识。平台确认重试不领取卡密，不渲染模板，不调用 IM。

| 情况 | 恢复行为 |
| --- | --- |
| 某段明确未发送，且允许重试 | 在尝试上限内仅重试该段，跳过全部已确认段 |
| 任意段超时、断线、异常或进程中断 | 标记 `NEED_MANUAL_CHECK`，永久保留原订单绑定，不自动重发 |
| A 全部确认，B 明确未发出 | 只重试 B，仍先查询官方订单状态 |
| A 全部确认，B 结果未知 | 先查询官方；已发货则完成，仍待发货时允许卖家单次授权 B 重试 |
| 官方已发货，A 有未知段 | 仅对齐 B；保留 A 的未知状态和人工核对警告 |
| 已关闭、退款中、身份变化、核验失败 | 暂停并保留卡密绑定，不执行出库或平台确认 |

**图片发送超时也属于未知结果。** “只补失败图片”只适用于能够证明该图片没有发出的失败，不能把普通网络超时解释成安全失败。现有 IM 网关对没有明确正面 ACK 的结果保守视为未知。

平台端的“已发货”只证明阶段 B，不能证明具体卡密和说明都已到达。只有 A 全部有明确回执、B 也已确认时，本地任务才完成。核对内容送达的底层服务要求操作人及证据引用；本轮没有开放通过 HTTP 随意将未知内容标为成功的接口。

## 冻结内容与图片

新任务入队时复制完整文本、说明、模板和规格到只读快照。图片复制到 `data/assets/.snapshots/<SHA256>.asset`，写入临时文件时使用 `data/tmp/` 并刷盘，再原子替换。数据库只保存相对路径和哈希。发送前重新验证冻结副本。

修改原素材不会改变已入队订单；新订单使用新版本。冻结副本损坏时阻断发送，不回退原图。库存不足任务同样保留入队版本。迁移前已存在的任务仍使用原相对引用及哈希，原图变化会阻断发送；不篡改历史快照。未知任务及其素材不自动清理。

所有新增持久数据在程序目录 `data/` 下。打包后根路径继续由 `sys.executable` 决定，移动完整目录不需要修改素材引用。

## 启动、网络重连与唤醒

启动先将遗留 `sending` 操作改为未知并保留卡密。已装配的官方运行时会在账号互斥锁内执行恢复扫描和官方对账，再处理新队列。IM 连接变化、官方查询失败以及时钟/调度超过 30 秒的间断均要求重新对账。

运行时每 5 秒检测连续性，并在发送边界再次检查，避免唤醒后的队列早于监测任务抢跑；同时暴露 `notify_resume()` 供后续 Windows 窗口宿主接入系统唤醒通知。对账失败维持暂停；离线不能据本地旧日志推断平台已完成。IM 未恢复时继续暂停内容发送。A 全部确认后的人工 B 补偿不依赖 IM 连接，但仍依赖新鲜的官方核验。

休眠/断电通过本地故障注入验证状态恢复；真实 Windows 电源通知、物理断电、托盘气泡和 EXE 便携包仍属于后续系统验收。

## 桌面安全工作台

先在 `apps/web` 运行 `npm run build`，再启动桌面后端。访问 `/desktop/safety`；默认地址为 `http://127.0.0.1:15177/desktop/safety`。`/health/ready` 返回 `safetyPage` 和 `safetyUiBuilt`，主入口继续兼容状态 JSON。

工作台显示待人工核对的红色警告、账号暂停/缺货提示、A/B 状态、各段状态、冻结素材和审计。默认启动是只读模式，真实运行时未装配时操作按钮禁用。

- “查询官方状态”：重新校验卖家、买家、订单、商品、规格、数量、金额和退款状态，仅对齐有证据的履约结果。
- “仅补发平台确认（阶段 B）”：要求 A 全部确认且最新官方状态仍为待发货；只允许一次 B 尝试。相同 `requestId` 不会再次执行，超时后先重新核验。
- 操作在账号执行锁内串行进行；请求必须携带启动时生成、仅存在内存的本机操作令牌。令牌通过同源页面专用请求获取，重启失效，响应禁止缓存；跨站请求被拒绝。它不替代 Windows 用户权限隔离。

接口：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/desktop/safety/session` | 同源页面获取短生命周期操作会话 |
| `POST /api/desktop/safety/records/{id}/reconcile` | 新鲜官方查询与安全对齐 |
| `POST /api/desktop/safety/records/{id}/retry-confirmation` | 带幂等请求编号的单次 B 补偿 |

## 验证入口

`apps/api/tests/test_delivery_safety.py` 包含数据库直接误改、并发库存、未知回执、原素材编辑、B 超时及请求重放、已发货但 A 未确认、身份变化、重启遗留发送和对账断网等测试。结合原有分段 Mock 测试、官方双监听测试、工作台前端测试与源码打包检查执行回归。

测试不访问真实平台，不使用真实卡密，不代表官方接口契约或账号接入已通过验收。
